# dsh-unity-pool v0.5.7 — 「多实例并存时绑定失效」修复（判据读数 / 变更点 / 回滚）

日期：2026-09-16 ｜ 插件目录：`C:\Users\Landrom\dsh-unity-pool` ｜ 版本：0.5.6 → **0.5.7**

## 1. 根因（一句话）

实例选择此前**只**依赖官方 session-scoped state（`set_active_instance` 按 `Mcp-Session-Id` 存），
而插件仅在本地镜像 `client.activeInstance` ≠ 绑定实例时才去激活；服务端 MCP 会话一旦被重建
（服务重启 / 会话被清理 / 编辑器域重载），本地镜像仍是陈旧的「已激活」→ 跳过激活 →
在**没有选择**的新会话上直发 `tools/call`。单实例时官方自动选中（掩盖问题），
**并存 2 个实例即被官方守卫拦死**（`Multiple Unity instances are connected … Available: [...]`）。

### 决定性复现（修复前，本机真机双实例 8090）

1. `unity_pool_bind(instance='_P2_前后挡A岛@de729c37c7ea39d4')` → 成功；`read_console` → 成功。
2. 取本会话 MCP session id（`debug_request_context` → `direct_properties.session_id = 27f0f7d1…`），
   服务端 `DELETE /mcp` 杀掉该会话（模拟服务重启/会话被清理）。
3. 再调 `execute_code` → **`{"success":false,"data":{"reason":"instance_selection_required",
   "available_instances":["_P2_前后挡A岛@de729c37c7ea39d4","_P4_总装车间E线@58bbafb55c1fd30b"]}}`**，
   且插件返回体 `success:true`（守卫错误被当成正常结果），此后**每次调用都如此**。

## 2. 官方侧事实（读实现，不是猜）

- 服务端源码：`E:\cache\uv\archive-v0\q6EuGhnYZoeTv1Q0SqZUE\Lib\site-packages\`
  - `transport/unity_instance_middleware.py`：实例选择存于 **FastMCP session-scoped state**
    （`ctx.set_state`，键前缀 = `ctx.session_id` = HTTP 的 `mcp-session-id` 头）；
    **同一个 middleware 还支持「每调用路由」**：`on_call_tool` 先从 arguments 里 `pop('unity_instance')`
    并直接解析（`_resolve_instance_value`），优先级高于 session state。
  - `transport/plugin_hub.py`：无目标实例且多会话时抛 `InstanceSelectionRequiredError`（即所见报错）。
- 实测（直连 8090，同一 session 先选后调）：session 内 `set_active_instance` 后调用正常；
  **全新 session 不带 session state，只带 `unity_instance` 参数 → 也正常**；
  两个并发 session 各自固定 P2 / P4 交错调用 → 各自命中自己的实例（互不干扰）。

## 3. 改了什么（五处）

| # | 文件 / 位置 | 变更 |
|---|---|---|
| ① | `lib/mcp-client.js` `callTool`（+ `_withInstanceArg`/`_rawCallTool`） | **每调用路由**：每次 `tools/call` 携带 `unity_instance=<绑定实例>`；`set_active_instance` 自身不加；老服务端不认识该参数时**自动降级**（`supportsPerCallInstance=false`，只降级一次） |
| ② | `lib/mcp-client.js` `activeInstance` getter/setter + `_request` | 本地镜像改为「值 + 所属 session」，会话重建/失效即作废（`sessionInvalid` 时显式清空） |
| ③ | `lib/index.js` `proxyMcp` | `client.pinnedInstance = 绑定实例`；`set_active_instance` **不再短路伪造成功**（真转发真结果）；遇到实例选择守卫 → 重建选择重试一次 → 仍失败返回 `success:false` + `【路由未生效】`（不静默改投）；激活失败不再直接 fail 而是记录原因 |
| ④ | `lib/index.js` `bind` / `_collectStateOnce` | 绑定后把实例钉到该会话的 MCP client（状态采集同样走每调用路由）；激活失败如实附 `activateError` |
| ⑤ | `lib/index.js` `_load` / `proxyMcp` | 绑定到扫描发现服务（`scan-N`）不再在热重载后被静默丢弃；陈旧绑定（服务的服务不在池中）给可读原因 |

版本：`package.json` 0.5.6→0.5.7；`mcp-client` clientInfo 同步；`lib/index.js` 头部注释 + `README.md` 变更日志已登记。
